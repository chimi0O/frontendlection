Адаптивная вёрстка и медиа-запросы

Резиновые раскладки, брейкпоинты, Mobile First. Как сделать лендинг удобным на iPhone, планшете и 4K-мониторе.

Зачем нужна адаптивность

Пользователи приходят с разных устройств: смартфоны, планшеты, ноутбуки, широкие мониторы. Один и тот же макет не может одинаково хорошо выглядеть на экране 375px и 2560px. Адаптивная вёрстка — способ сделать так, чтобы сайт работал везде.

Для рекламного сайта адаптивность критична: большая часть трафика — мобильная, а неудобный интерфейс на телефоне напрямую снижает конверсию.

Важно

Мобильная версия — это не «уменьшенная десктопная». Это отдельный сценарий использования: другой палец, другое расстояние до глаз, другой контекст. Проектировать нужно с мобильного (Mobile First).

Резиновые раскладки

Первый шаг к адаптивности — отказ от фиксированных ширин. Блоки должны растягиваться и сжиматься вместе с экраном. Для этого используют относительные единицы:

  • % — процент от родителя.
  • vw / vh — процент от ширины / высоты окна.
  • rem — относительно размера шрифта корня.
  • fr — доля свободного пространства в Grid.
  • max-width — ограничение максимальной ширины, чтобы контент не растягивался бесконечно.

Резиновая раскладка — база. Но её недостаточно: на очень узком экране трёхколоночный макет всё равно сломается. Здесь на помощь приходят медиа-запросы.

Медиа-запросы

Медиа-запрос — правило CSS, которое применяется только при определённых условиях: ширине экрана, ориентации, разрешении.

Media Query
CSS-конструкция @media, которая применяет стили только при выполнении условия (например, ширина экрана меньше 768px). Основа адаптивной вёрстки.

Пример:

  • @media (max-width: 768px) { ... } — стили для экранов до 768px.
  • @media (min-width: 1024px) { ... } — стили для экранов от 1024px.
  • @media (orientation: landscape) { ... } — для горизонтальной ориентации.

Брейкпоинты

Брейкпоинт — точка, в которой макет меняется. Не «под iPhone», а «под момент, когда текущая раскладка ломается». Хорошая практика — выбирать брейкпоинты по контенту, а не по конкретным устройствам.

Брейкпоинт (Breakpoint)
Ширина экрана, при которой макет перестраивается: меняется количество колонок, скрываются второстепенные блоки, увеличиваются отступы. Выбирается по контенту.

Типичные брейкпоинты:

  • 320–480px — мобильные.
  • 481–768px — большие телефоны, маленькие планшеты.
  • 769–1024px — планшеты.
  • 1025–1280px — ноутбуки.
  • 1281px+ — широкие мониторы.

Mobile First

Подход Mobile First означает, что базовые стили пишутся для мобильного, а затем через min-width добавляются стили для больших экранов. Это удобнее, чем «сжимать» десктопный макет.

Почему:

  • Проще расставить приоритеты: на маленьком экране видно, что действительно важно.
  • Меньше лишнего кода: не нужно переопределять стили для мобильного.
  • Совпадает с реальным трафиком: большинство пользователей — мобильные.

Адаптивные изображения и типографика

Адаптивность — не только блоки. Изображения и текст тоже должны подстраиваться:

  • max-width: 100% для изображений — чтобы не вылезали за контейнер.
  • srcset и sizes — разные версии изображения для разных экранов.
  • clamp() для шрифтов — плавное изменение размера между минимумом и максимумом.
  • Относительные единицы (rem, em) вместо фиксированных px для текста.
Для рекламы

Адаптивность — не «техническая деталь», а часть конверсии. Если на телефоне кнопка уезжает за экран или форма не помещается — пользователь уходит. Проверка на реальных устройствах обязательна.

Итог

Адаптивная вёрстка — сочетание резиновых раскладок, медиа-запросов и продуманных брейкпоинтов. Вместе с Mobile First и адаптивными изображениями они делают сайт удобным на любом устройстве — а значит, работающим на конверсию.
